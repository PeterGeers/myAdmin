# Deploy environment-variable audit (test-environment spec, Phase 6 Task 44)

Name-only mapping of deploy environment variables to the code that consumes them, the
overlaps/duplicates, and the target per-plane set. **No secret VALUES are recorded here**
(Req 44.1/44.4) — only variable NAMES. Generated by auditing `backend/src`, `frontend/src`,
and the deploy workflows.

## 44.2 — overlaps / duplicates (intentional vs redundant)

- **Cognito identity block vs registry** (REDUNDANT): `COGNITO_USER_POOL_ID` /
  `COGNITO_APP_CLIENT_ID` / `COGNITO_REGION` / `COGNITO_CLIENT_ID` are superseded by
  `COGNITO_POOL_KEYS` + `{KEY}_COGNITO_*`. Retire from Railway once the registry is the
  sole config (Task 43.3), unless the registry-absent single-pool fallback is still wanted.
- **`TEST_COGNITO_*` vs registry** (REDUNDANT): the test-pool loader
  (`auth/test_pool_config.py`) predates the registry; a `MYADMIN`/test key in the registry
  covers the same pool.
- **`VITE_TEST_COGNITO_*` vs `VITE_COGNITO_*`** (REDUNDANT for selection): the frontend
  resolver selects the pool from `VITE_APP_ENV`, so a second per-env VITE pair is no longer
  needed for pool selection.
- **`MYSQL_*` vs `DB_*`** (INTENTIONAL, different layers): `MYSQL_*` are the local Docker
  container's init vars; `DB_*` are the app's connection vars. Keep both, documented.
- **CloudFront trio** (INTENTIONAL): domain vs full URL vs KVS ARN are distinct values.
- **`SIGNUP_COGNITO_*`, `PROMO_DB_NAME`** (INTENTIONAL): distinct features, not duplicates.

## 44.3 — target per-plane variable set (per environment)

- **Selector:** `APP_ENV` (backend), `VITE_APP_ENV` (frontend).
- **Backend_Identity:** `COGNITO_POOL_KEYS` + `{KEY}_COGNITO_ISSUER/_JWKS_URI/_CLIENT_ID/_POOL_LABEL`
  + `COGNITO_CLIENT_SECRET` (secret). Drop the legacy identity block.
- **MySQL:** PRODUCTION `DB_HOST/PORT/USER/PASSWORD` + TEST `DB_*_TEST`; schema `finance`
  both. Drop `TEST_DB_NAME`/`testfinance`.
- **SAM:** table names come from samconfig per stack (not Railway); the SPA needs
  `VITE_MEMBERS_API_BASE_URL`.
- **Frontend:** `VITE_API_URL`, `VITE_COGNITO_*`, redirect/domain/docs/CloudFront vars.
- **Secrets:** env-sourced only (see list); never committed.

## 44.4 — leaked-secret check

- No secret VALUES are committed in the repo (the committed definitions use references /
  placeholders — verified by the Task-42.5 no-placeholder test and the pre-push secret
  scanner). The repo-root `.env` and `frontend/.env.local` are gitignored.
- No rotation recommended on the basis of this audit (no committed-plaintext secret found).
  If any secret has ever been committed in history, rotate it out of band.

## Findings (follow-ups, out of scope for the audit itself)

1. **STALE `TEST_MODE`/`TEST_DB_NAME` in `routes/system_health_routes.py`** — reports a
   `testfinance` DB name, contradicting the Phase-3 APP_ENV model (schema is always
   `finance`; there is no `testfinance`). Should be updated to report the resolved target.
   *Separate change, not Task 44.*
2. **Google-Drive `TEST_MODE` folder toggle** is orthogonal to `APP_ENV` and still valid,
   but is a candidate to fold into the resolver so there is ONE environment selector.
3. **Legacy Cognito identity-block + `TEST_COGNITO_*` + `VITE_TEST_COGNITO_*`** can be
   dropped from Railway/GitHub once confirmed unused (Task 43.3).
